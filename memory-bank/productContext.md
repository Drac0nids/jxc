# 产品上下文（Product Context）

## 1. 为什么要做这个项目
传统中小商贸企业在进销存管理中常见问题：
- 库存数据分散、更新滞后，导致缺货与积压并存。
- 线下扫码、开单、盘点流程依赖人工，效率低、差错多。
- 多门店/多人员协同缺乏统一数据中心。

本项目（极速云进销存）通过多租户 SaaS 化交付，为商家提供低门槛、可扩展的统一业务系统。

## 2. 核心用户与场景
- **核心用户**：中小企业老板、仓管、采购、销售、门店店员。
- **关键场景**：
  - 扫码入库、出库与库存调整。
  - 商品信息维护（SKU、条码、价格、单位）。
  - 多端协同：办公室桌面端 + 仓库/门店移动端。

## 3. 产品价值主张
- **准确**：库存与成本计算可审计、可追溯。
- **高效**：扫码和移动作业减少手工录入。
- **协同**：统一云端数据，降低多终端信息不一致。
- **可运营**：支持租户隔离、鉴权、安全与备份策略。

## 4. 体验目标
- 请求响应统一规范，错误可定位（`request_id`）。
- 用户鉴权流程一致，租户数据天然隔离。
- 业务高峰时库存变更仍保持正确性（事务 + 行级锁）。
- Android 端具备离线优先体验，网络不稳定时不中断作业。

## 5. 当前产品文档完整性
- 已形成可研发实施的 v1.1 文档基线（PRD/ADD/API）。
- 关键业务与规范已明确：
  - 功能优先级（P0/P1/P2）与验收标准。
  - 全量核心 API 清单、字段约束、错误码。
  - 幂等、离线同步与库存一致性规则。
